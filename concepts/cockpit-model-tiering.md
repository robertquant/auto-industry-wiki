# 座舱模型分层架构 (Cockpit Model Tiering)

## 定义
座舱大模型的一种部署范式：**小模型常驻车端**承担低延迟/离线任务，**大模型置于云端按需唤醒**承担重负载推理。核心是在车端算力、功耗、成本与模型能力之间做分层，而非把所有能力堆在一个车端大模型上。

## 2026年9月格局

| 玩家 | 分层方式 |
|------|----------|
| 奔驰 Momentum | 1个小模型常驻车端，其余云端按需唤醒 |
| Jetta M6 | 3个模型分层 |
| 特斯拉语音 | 2个模型分层 |
| 理想 Mind GPT | 端到端智能体 + 180亿量级投入，座舱响应提升5倍 |

## 为什么分层

1. **延迟**：常驻小模型保证离线可用、唤醒/响应在本地完成，云端往返时延不可接受
2. **功耗与算力**：车端 SoC 算力有限，大模型全量上车成本与散热不可行
3. **成本**：云端按需调用摊薄单次推理成本，避免为低频重任务常驻大模型
4. **合规**：涉及用户数据的部分可本地闭环

## 与端云协同的关系

分层架构是「端云协同」的具体形态——早期端云协同偏笼统（本地小模型+云端大模型），2026年演进为**明确的分层模型数量与职责划分**（几个模型、谁常驻、谁按需）。

## 判断

1. 分层数量成为新的产品参数——「几个模型、几层」正在取代「多大参数」成为座舱卖点
2. 奔驰（传统豪华）与特斯拉（新势力标杆）同时采用分层，说明这是跨阵营的架构收敛
3. 自研+备案合规（如理想Mind GPT）决定车企能否掌握分层中的「常驻层」——外采模型很难做到离线常驻
