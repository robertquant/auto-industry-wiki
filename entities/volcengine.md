# 火山引擎

## 概述
火山引擎，字节跳动旗下云服务平台，提供车机大模型解决方案。核心产品为豆包大模型，是字节跳动"上车"战略的核心载体。

## 车载大模型规模
- **搭载规模**：700万+辆车、50+品牌、145款车型
- **争议**：700万数字来源不明，可能是累计装机量而非活跃用户

## 2026年6月动态

### 赛豆科技AIVA品牌发布
- **合作模式**：火山引擎提供豆包座舱大模型
- **品牌定位**："先有AI，再有车"
- **战略意义**：字节跳动以技术服务商身份正式入局汽车智能化
- **差异化**：类似华为Hi模式但更轻量级，不做全栈智驾

### 高通AI Agent能力展示
- **技术展示**：记忆、识别、情感提醒
- **竞争态势**：高通、火山引擎、DeepSeek在座舱AI领域竞争加剧

## 合作案例
- **赛豆科技**：2026年6月首发，AI定义汽车核心卖点
- **其他品牌**：50+品牌已合作（具体名单待补充）

## 竞争格局

| 竞争对手 | 路线 | 特点 |
|----------|------|------|
| 华为鸿蒙 | 全栈智驾+座舱 | Hi模式，重资产 |
| DeepSeek | 开源大模型 | 45.2%份额领先，吉利/东风/广汽接入 |
| 火山引擎 | 座舱AI轻量化 | 不造车，提供AI能力 |

## 战略定位
- 字节跳动"上车"战略的核心载体
- 不造车，提供AI能力
- 类似华为Hi模式但更轻
- 验证科技巨头以技术服务商身份切入汽车产业的路径

## 2026年6月：字節AI转向B端

### 豆包经营数据

| 指标 | 数据 |
|------|------|
| 日活 | **2亿+** |
| 日收入 | **<100万元** |
| 日算力成本 | **数千万** |

### 战略转向

- **核心问题**：日活2亿但收入不及成本1/10，C端模式烧补贴难以为继
- **转向B端**：**Seedance ARR达20亿美元**，月收入>10亿
- **对比**：B端收入是C端的100倍+，商业模式出现根本性差异
- **导火索**：到访Anthropic后调整战略，重新认知AI商业化路径

### 判断
豆包证明了AI可以做到2亿日活，但也证明了C端AI的商业化困境——"用户免费习惯+算力成本高企"的矛盾。ByteDance转向B端（Seedance）是务实的商业化选择，火山引擎的车载大模型可能成为新的增长点。

### 豆包上车规模（2026-09-25）
- **已上车超 700 万辆**（50+ 品牌、145 款车型）
- 日均车内交互超 **3000 万次**
- **判断**：豆包是座舱大模型“上车规模”最大的第三方之一，但按 [[cockpit-ai-barrier-layering]] 框架，模型层属“弱壁垒”——规模优势不等于护城河。

## 2026-11-10 更新：扣子企业版退场——低代码中间层被 Agent 抹平（36氪）
- **扣子（Coze）企业版退场**：2025 年以 **19.3% 市占**居中国 AI Agent 构建平台第一，**10/29 停售、2027/12/31 下线**——字节在低代码 Agent 构建层的战略收缩
- 判断：低代码/可视化编排的「中间抽象层」正被端到端 Agent（大模型直接执行）抹平——对车企工具链的启示：直接 Agent 化，不要新建中间抽象层（呼应 [[ai-coding-tools-2026]]、[[agentic-coding-capability-2026]]）；火山引擎主赛道（豆包上车，页首已录）不受影响，扣子退场 = 字节资源向模型/云端收敛的信号
